DistSys diagram demo

Services, a hub, and a list of events: mermaid.run() calls bindFunctions automatically once each SVG below is inserted, so every event's orbs start streaming with no extra wiring.

Basic stream (service → hub)

distsys-beta
services:
  - id: orders
    label: Order Service
hub:
  id: bus
  label: Event Hub
events:
  - id: order-created
    label: OrderCreated
    interval: 300
    from: orders
    to: bus

Round trip: service → hub, then hub → service

events is a list — two events between the same service and hub, going opposite directions, render as two parallel lines instead of overlapping, and animate independently. 

distsys-beta
services:
  - id: orders
    label: Order Service
hub:
  id: bus
  label: Event Hub
events:
  - id: order-created
    label: OrderCreated
    interval: 500
    from: orders
    to: bus
  - id: order-confirmed
    label: OrderConfirmed
    interval: 500
    from: bus
    to: orders

Multiple services, direct service → service line

event.from/event.to also work between two services directly, bypassing the hub entirely — the hub still renders (spanning both services) but this particular event's line runs straight across. 

distsys-beta
services:
  - id: orders
    label: Order Service
  - id: payments
    label: Payment Service
hub:
  id: bus
  label: Event Hub
events:
  - id: payment-requested
    label: PaymentRequested
    interval: 500
    from: orders
    to: payments

Controlling the stream from the page

mermaidAPI.render() returns bindFunctions; calling it on the live SVG attaches a .distSys controller with play(), pause(), stop(), and setPathVisible() / togglePath() for the connecting line(s). With multiple events, these apply to all of them at once; svgEl.distSys.events['stock-reserved'] reaches a single one.
